# CR450AF at 400 km/h: a photoreal film built entirely from Python

A 65-second film of China's CR450AF *Fuxing* running at its 400 km/h design speed across a misty tower-karst
valley at golden hour, then through a cutting into a tunnel. Everything (train, railway, landscape, camera
work, physics and sound) is generated by Python in **Blender 5.3 (bpy) / Cycles** and rendered on
**GitHub Actions** with 20 parallel jobs.

Unreal Engine was evaluated first: this project's build machine has **no GPU** (4 CPU cores), and Unreal's
renderer needs a capable GPU (and its download host is not reachable here), so Blender/Cycles on CPU is used.

## Layout
| Path | What |
|---|---|
| `film/specs.py` | every published/measured number (train, track, OCS, curve) |
| `film/trainshape.py` | parametric nose/body loft fitted to calibrated photos |
| `film/livery.py` | livery, panel gaps, lettering, road dirt, insect marks → textures |
| `film/train.py`, `film/trainparts.py` | 8-car set: shells, bogies, 920 mm wheelsets, pantographs, gangways, interiors, cab |
| `film/alignment.py` | clothoid/arc alignment, cant, track frames (pure numpy) |
| `film/infra.py` | viaduct, piers, CRTS III slab track, CHN60 rails, WJ-8 fasteners, OCS with stagger, noise barriers |
| `film/world.py` | terrain, karst towers, paddies, river, vegetation scatter with wind + slipstream, sky, haze |
| `film/wake.py` | leaves & dust lifted by the train's slipstream (simulated, baked to shape keys) |
| `film/shots.py` | the nine shots with real camera speeds and lenses |
| `film/build.py` | builds the complete animated scene into one `.blend` |
| `film/audio.py` | sound synthesised from the same kinematics (Doppler, air absorption), EBU R128 master |
| `film/physics.py` | per-frame physics log (speed, wheel rate, camera speed/distance) |
| `tools/render_frames.py` | interleaved, resumable frame renderer (one matrix job) |
| `tools/encode.py` | validates every PNG, encodes H.264 BT.709 + audio, ffprobe checks, two-pass <25 MB copy |
| `tools/match_ref.py` | solves the camera of a reference photo and renders the model from it |
| `.github/workflows/render.yml` | build once → N render jobs (20 at a time) → collect/encode/commit |
| `docs/RESEARCH.md` | specifications, measurements, standards, sources |

## Run locally
```
pip install -r requirements.txt            # Python 3.13.18, bpy 5.3.0
python tools/fetch_assets.py assets        # pinned CC0 assets (Poly Haven)
python -m film.build --assets assets --out build/scene.blend --quality preview
python tools/render_frames.py --blend build/scene.blend --out frames --frames 100,1000
python -m film.audio build/audio.wav
```

## Render in the cloud
Actions → *render-film* → Run workflow (`quality`: preview/final, `jobs`: 20 or more). Job *k* renders
frames *k*, *k+N*, *k+2N*, … Failed jobs can simply be re-run: finished frames are reused. The encode job
refuses to run with missing or incomplete frames, then commits the MP4 and an Instagram copy (<25 MB) to `output/`.
